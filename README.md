# 言外之意 · 提示词挑战赛（20 题完整版 · 本地运行）

20 题、60 分钟、每题 5 分，总分 100 分；真实调用 DeepSeek V4.1 Flash。

## 启动

需要 Python 3.10 或更新版本，不需要安装第三方运行依赖。

```bash
git clone https://github.com/WANG5294/Prompt-Competition.git
cd Prompt-Competition
cp .env.example .env
# 按下方说明编辑 .env，填入自己的 API key 后再启动
python3 server.py
```

浏览器打开 **http://127.0.0.1:8765**。

- 账号：`123456`
- 密码：`mock`
- 登录后点击“开始挑战”，启动 60 分钟倒计时。
- 端口被占用时：`python3 server.py --port 8766`，然后打开对应地址。

这是 HTML/CSS/JavaScript 前端搭配 Python 后端的网站，不能通过双击 HTML 完成登录与 API 判分。后端必须保持运行。本地服务仅监听本机回环地址。

## 模型配置

仓库不包含 API key，需要自行配置。密钥仅由 Python 后端读取，不能填入 HTML 或 JavaScript。

1. 在 DeepSeek 开放平台创建自己的 API key。
2. 在项目根目录（与 `server.py` 同级）复制 `.env.example` 为 `.env`：Linux/macOS 使用 `cp .env.example .env`；Windows PowerShell 使用 `Copy-Item .env.example .env`。已有 `.env` 时直接编辑，不要覆盖原配置。
3. 用文本编辑器打开 `.env`，在 `DEEPSEEK_API_KEY=` 后粘贴真实密钥，不加引号。保存后的内容如下（将“你的密钥”替换为实际值）：

```dotenv
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_MODEL=deepseek-flash
```

4. 启动 `python3 server.py`；如果服务已经运行，先停止再重新启动，配置才会生效。

未配置密钥时可以登录和浏览题目，但调用模型判分会提示配置错误。补上密钥并重启后，可对失败的原答案点击重试。`.env` 已加入 `.gitignore`，不要提交它；`.env.example` 只保留空密钥，供他人复制使用。比赛数据库和浏览器测试截图也不会上传。

官方型号核对：https://api-docs.deepseek.com/quick_start/pricing

固定 HTTPS 地址为 `https://api.deepseek.com/chat/completions`；非思考模式、temperature=0、max_tokens=512；仅发送选手提示词，不把谜底附加给模型。模型可能存在随机性。真实判分和失败后的重试可能产生 API 费用。

## 实现的功能

- 登录、退出、服务端会话；登录 Cookie 为 HttpOnly、SameSite=Strict。
- 20 道由浅入深的题目，首题“苹果”、末题“黄仁勋的皮夹克”；完整题库见 [QUESTION_DESIGN.md](QUESTION_DESIGN.md)。
- 本地手动开赛；服务端检查时间，刷新或重新登录不重置考试。
- 浏览器保存未提交草稿，SQLite 保存正式答案、模型输出、分数、原因和模型名。
- 每个账号每题唯一约束；重复提交返回原记录，不能覆盖答案。
- 提交持久化后，三个后台工作线程从数据库任务表领取判分任务。
- API 错误不计零分，可重试锁定的原答案；截止前受理的答案可在结束后继续判分。
- 服务重启后，排队任务继续执行，运行中断的任务转为可手动重试状态。登录会话保存在内存，重启后需重新登录。
- 屏蔽词命中直接零分，不调用 API；模型输出截断或失败显示待处理。

## 本地测试评分约定

严格顺序：屏蔽词检查 → 精确匹配 5 分 → 白名单修饰 4 分 → 包含谜底且额外字符 0～30 个为 2 分 → 包含谜底且额外字符至少 31 个为 1 分 → 不含谜底为 0 分。

忽略模型输出首尾空白；谜底须连续出现。额外字符按 Python Unicode 字符计数，包含标点、内部空格、换行，并只扣除一次谜底长度。屏蔽词使用 NFKC、大小写归一化，去除空白和零宽格式字符后进行子串匹配。

4 分白名单及完整约定在页面底部“评分规则与测试说明”中展示。**测试版没有语义识别功能**，“不是苹果”等含有谜底但存在否定、矛盾或非修饰成分的文本仍按长度判定，正式比赛前需确认或补充规则。

## 切后台罚时（无声音）

第 n 次切后台扣除 `30 × n` 秒，累计 `15 × n × (n+1)` 秒。因此第 1、2、3 次分别罚时 30、60、90 秒，累计 30、90、180 秒。截止时间 = 开赛时间 + 3600 秒 − 累计罚时。后端在同一事务中记录事件、计算次数及罚时；重复事件只处理一次。罚时耗尽剩余时间时立即禁止新提交，已受理答案继续判分。

检测范围沿用上一版：标签页隐藏、窗口失焦、离开页面；同一次离开触发的多个事件合并。点击地址栏、系统对话框等也可能失焦并计次，页面已提前告知。不会播放任何声音。弹窗显示服务端确认的次数及累计罚时，关闭提醒不会撤销处罚。答完 20 题后仍检测到有效截止时间。

断网时事件保存到浏览器，恢复后补传；存在待同步事件时前端禁止新提交，避免用旧截止时间继续交卷。服务器接受发生在调整后有效作答时段内的补传事件，截止后的事件不再加罚。已受理的提交不因更晚到达的离开记录追溯撤销。多终端和篡改脚本仍可绕过客户端信号，此功能不等同于安全考试浏览器。

事件表 `focus_events` 保存每次罚时秒数；旧版只有提醒的记录保留但不追溯扣时，也不计入新规则的 n。客户端旧版未同步提醒队列不转为处罚。

普通网页无法强制禁止切后台，无法保证关闭、崩溃或禁用脚本后的完整记录。参考：[页面可见性](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)。

## 数据版本

20 题版使用新的 `data/contest-v2.sqlite3`，提供全新的 60 分钟赛程。原三题版数据库 `data/contest.sqlite3` 完整保留，没有删除或覆盖旧答案。前三题题目与屏蔽词兼容旧版，但新版不会把旧赛程成绩混入新赛程。可用环境变量 `CONTEST_DB` 指定其他数据库。

## 从头测试

停止服务器后，将 `data/contest-v2.sqlite3` 以及若存在的 `data/contest-v2.sqlite3-wal`、`data/contest-v2.sqlite3-shm` 移动到备份目录，再重新启动，即可创建全新比赛。不要在服务运行时移动数据库文件。

浏览器的未提交草稿独立保存；需要时可以选中输入框内容删除，或清除该站点的浏览器存储。
